1.2 Memory Management (Labs 5/6)

ในโปรแกรมมีการตรวจสอบ RAM ก่อนที่จะอนุญาตให้ Job ทำงาน

ระบบใช้ตัวแปร available_ram_gb เพื่อตรวจสอบว่า RAM
ที่เหลืออยู่เพียงพอกับที่ Job ต้องการหรือไม่

โปรแกรมใช้ while loop ลักษณะดังนี้

while True:
    ตรวจสอบ Available RAM
    ถ้า RAM เพียงพอ
        จัดสรร RAM ให้ Job
        แล้วออกจาก loop
    ถ้า RAM ไม่เพียงพอ
        รอแล้วตรวจสอบใหม่อีกครั้ง

วิธีนี้ช่วยป้องกันไม่ให้ระบบจัดสรร RAM เกินกว่าที่มีจริง

เช่น ถ้ามี RAM ไม่พอ ระบบจะไม่รีบเริ่ม Job เพิ่ม
แต่จะให้ Job รอจนกว่างานอื่นจะเสร็จและคืน RAM กลับมา

วิธีนี้ช่วยลดโอกาสที่ระบบจะใช้หน่วยความจำเกินขนาด
จนต้อง Swap ข้อมูลไปยัง Disk บ่อย ๆ และเกิด Thrashing


1.3 Concurrency & Deadlocks (Labs 3/4)

ในส่วนการจัดสรร GPU โปรแกรมใช้

sorted_gpus = sorted(req_gpus)

ก่อนที่จะ Lock GPU ที่แต่ละ Job ต้องการ

การเรียงลำดับ GPU ก่อนทำการ Lock ทำให้ทุก Job
พยายามขอ Resource ตามลำดับเดียวกัน

ตัวอย่างเช่น Workload A ขอ GPU

[2, 1, 0]

แต่ก่อน Lock โปรแกรมจะเรียงเป็น

[0, 1, 2]

การบังคับให้ Process ขอ Resource ตามลำดับเดียวกัน
ช่วยลดโอกาสเกิด Circular Wait ซึ่งเป็นหนึ่งในเงื่อนไข
ที่ทำให้เกิด Deadlock

ดังนั้นการใช้ Resource Hierarchy โดยจัดลำดับ GPU
ก่อนการ Acquire Lock จึงเป็นวิธีที่ช่วยหลีกเลี่ยง Deadlock


2. Hardware Utilization

จากการทดลอง ระบบสามารถให้ Workload A, Workload B
และ Workload C ทำงานพร้อมกันได้ เพราะแต่ละ Workload
ไม่ได้ใช้ทรัพยากรเหมือนกันทั้งหมด

Workload A เป็น Distributed Training
ใช้ RAM 40 GB และ GPU 0, 1 และ 2

หลังจาก Workload A ได้ RAM 40 GB แล้ว
ระบบยังเหลือ RAM อีก 24 GB

จากนั้น Workload B ใช้ RAM 16 GB และไม่ใช้ GPU เลย
จึงสามารถทำงานด้วย CPU พร้อมกับ Workload A ได้

หลังจากนั้น Workload C ใช้ RAM เพียง 2 GB และต้องการ GPU 3

เนื่องจาก GPU 0, 1 และ 2 ถูก Workload A ใช้งานอยู่
แต่ GPU 3 ยังว่าง Workload C จึงสามารถใช้ GPU 3
และทำงานพร้อมกับ Workload A และ B ได้

ดังนั้นทั้ง 3 งานจึงไม่จำเป็นต้องรอกันทั้งหมด เพราะ OS
สามารถจัดสรร Resource ที่แตกต่างกันให้แต่ละงานได้

Workload A ใช้ GPU 0, 1, 2
Workload B ใช้ CPU และไม่ใช้ GPU
Workload C ใช้ GPU 3

รวม RAM ที่ทั้งสามงานใช้พร้อมกันคือ

40 + 16 + 2 = 58 GB

ซึ่งยังไม่เกิน RAM ทั้งหมด 64 GB

จึงทำให้ระบบสามารถรันทั้งสาม Workload พร้อมกันได้
โดยไม่ใช้ RAM เกินขนาด และไม่เกิดการแย่ง GPU ตัวเดียวกัน

แนวคิดนี้แสดงให้เห็นว่า Operating System สามารถเพิ่ม
Hardware Utilization ได้โดยจัดสรรทรัพยากรที่ยังว่าง
ให้กับงานอื่นแทนที่จะปล่อยให้ทรัพยากรว่างอยู่

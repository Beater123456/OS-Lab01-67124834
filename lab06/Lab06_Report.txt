1. FIFO vs LRU (Phase 2)

จากการทดลอง ผมพบว่า FIFO เกิด Page Fault จำนวน 9 ครั้ง
ในขณะที่ LRU เกิด Page Fault จำนวน 7 ครั้ง จึงเห็นได้ว่า
LRU ทำงานได้ดีกว่าสำหรับชุดข้อมูลที่ใช้ในการทดลองนี้

สาเหตุคือ FIFO จะเลือกเอา Page ที่เข้ามาอยู่ใน RAM ก่อนออกไปก่อน
โดยไม่ได้สนใจว่า Page นั้นเพิ่งถูกใช้งานหรืออาจจะถูกใช้งานอีกในเร็ว ๆ นี้
จึงมีโอกาสนำ Page ที่ยังจำเป็นออกจาก RAM และทำให้ต้องโหลด Page
นั้นกลับเข้ามาใหม่ จึงเกิด Page Fault เพิ่มขึ้น

ส่วน LRU จะดูว่า Page ไหนไม่ได้ถูกใช้งานมานานที่สุด แล้วเลือก Page
นั้นออกจาก RAM ถ้ามีการเรียกใช้ Page ใดล่าสุด Page นั้นจะถูกเลื่อนไป
เป็น Page ที่เพิ่งถูกใช้งาน ทำให้ LRU สามารถเก็บ Page ที่มีแนวโน้มว่า
จะถูกใช้งานซ้ำไว้ใน RAM ได้ดีกว่า

จากผลที่ผมทดลองจริง LRU จึงมี Page Fault เพียง 7 ครั้ง
ซึ่งน้อยกว่า FIFO ที่มี 9 ครั้ง


2. Understanding Thrashing (Phase 3)

จากความเข้าใจของผม Thrashing คือสถานการณ์ที่ RAM มีพื้นที่ไม่เพียงพอ
จนระบบต้องเสียเวลาในการย้ายหรืออ่านเขียนข้อมูลระหว่าง RAM กับ Disk
บ่อยมาก แทนที่จะใช้เวลาส่วนใหญ่ไปกับการประมวลผลงานจริง

จากการทดลอง Scenario 1 ซึ่งข้อมูลสามารถอยู่ใน RAM ได้
ใช้เวลาประมาณ 0.3219 วินาที

แต่ Scenario 2 ซึ่งจำลองการเกิด Thrashing โดยมีการอ่านและเขียนข้อมูล
กับ Disk ซ้ำ ๆ ใช้เวลาประมาณ 0.6763 วินาที

ดังนั้น Scenario 2 ใช้เวลามากกว่าและในการทดลองของผมระบบช้าลง
ประมาณ 2 เท่า

สาเหตุที่ Scenario 2 ช้ากว่า เพราะการเข้าถึงข้อมูลบน Disk ใช้เวลามากกว่า
การเข้าถึงข้อมูลที่อยู่ใน RAM และเมื่อระบบต้องอ่านและเขียน Disk
ซ้ำหลายครั้ง เวลาส่วนหนึ่งจึงถูกใช้กับงาน I/O แทนการประมวลผลหลัก


3. AI Engineering Decision

ถ้าผมกำลัง Train AI Model แล้ว RAM เต็มจนเกิด Thrashing
วิธีหนึ่งที่สามารถช่วยได้คือการลดค่า batch_size

batch_size คือจำนวนข้อมูลที่ Model นำมาประมวลผลพร้อมกันในแต่ละรอบ
ถ้ากำหนด batch_size สูงเกินไป โปรแกรมจะต้องใช้หน่วยความจำมากขึ้น
และอาจใช้ RAM เกินกว่าที่เครื่องมีอยู่

เมื่อเราลด batch_size จำนวนข้อมูลที่ต้องเก็บและประมวลผลพร้อมกัน
ก็ลดลง ทำให้โปรแกรมใช้ RAM น้อยลง เมื่อ RAM มีพื้นที่เพียงพอ
ระบบปฏิบัติการก็ไม่จำเป็นต้องย้ายข้อมูลระหว่าง RAM กับ Disk
บ่อยเหมือนเดิม

ดังนั้นการลด batch_size สามารถช่วยลดการเกิด Thrashing
และช่วยให้ระบบกลับมาใช้เวลาในการประมวลผลจริงมากขึ้น
แทนที่จะเสียเวลากับการ Swap ข้อมูลระหว่าง RAM และ Disk

2. I/O Bound Concept

จากความเข้าใจของผม I/O Bound คือสถานการณ์ที่ประสิทธิภาพของงาน
ถูกจำกัดด้วยความเร็วในการอ่านหรือเขียนข้อมูลจากอุปกรณ์ I/O
เช่น HDD หรือ SSD มากกว่าความเร็วของ CPU

เมื่อโปรแกรมต้องรอข้อมูลจาก Disk CPU จะไม่สามารถประมวลผล
ขั้นตอนต่อไปได้ทันที เพราะข้อมูลที่ต้องใช้ยังมาไม่ถึง

ดังนั้นในช่วงที่ระบบเป็น I/O Bound CPU ไม่จำเป็นต้องทำงานที่
100% ตลอดเวลา แต่จะมีช่วงที่ CPU ว่างหรือรอข้อมูลจาก Disk อยู่มาก

ปัญหานี้ทำให้ระบบโดยรวมช้าลง แม้ว่า CPU จะมีความเร็วสูงก็ตาม
เพราะความเร็วของงานถูกจำกัดด้วย I/O ที่ช้ากว่า CPU และ RAM


3. AI Industry Connection (Phase 3)

จากการทดลองของผม การอ่านไฟล์เล็กจำนวน 1,000 ไฟล์

แต่การอ่านไฟล์ใหญ่ไฟล์เดียวที่รวมข้อมูลไว้แล้ว
ใช้เวลาเพียง 0.0011 วินาที

สาเหตุคือเมื่อ Dataset มีไฟล์ .jpg จำนวนมาก เช่น 1,000,000 ไฟล์
ระบบปฏิบัติการต้องเปิดไฟล์ อ่านข้อมูล และปิดไฟล์ซ้ำ ๆ
เป็นจำนวนมาก

นอกจากนี้ OS ยังต้องค้นหา Inode ตรวจสอบ Permission
และจัดการการเข้าถึง Disk สำหรับแต่ละไฟล์
จึงทำให้เกิด I/O Overhead สูง

ในงาน AI ถ้า GPU ต้องรอข้อมูลจาก Disk เป็นเวลานาน
GPU จะไม่มีข้อมูลให้ประมวลผล ถึงแม้ GPU จะมีประสิทธิภาพสูง
ก็อาจต้องว่างและรอข้อมูล ซึ่งเรียกว่า GPU Starvation

แต่ถ้านำข้อมูลจำนวนมากมารวมไว้ในไฟล์แบบต่อเนื่อง
เช่น TFRecord, WebDataset หรือ HDF5
ระบบสามารถเปิดไฟล์เพียงครั้งเดียวและอ่านข้อมูลแบบ Sequential
ต่อเนื่องได้

วิธีนี้ช่วยลดจำนวนครั้งของการเปิดและปิดไฟล์
ลด I/O Overhead และส่งข้อมูลให้ GPU ได้ต่อเนื่องมากขึ้น

ดังนั้นการจัด Dataset ให้อยู่ในรูปแบบ Sequential
สามารถช่วยลดปัญหา I/O Bound และทำให้การ Train AI
ใช้ทรัพยากร GPU ได้มีประสิทธิภาพมากขึ้น

1. The Convoy Effect (Phase 2)

จากความเข้าใจของผม Convoy Effect คือปัญหาที่ Process ขนาดเล็ก
ต้องรอ Process ขนาดใหญ่ที่อยู่ข้างหน้าทำงานจนเสร็จก่อน
แม้ว่างานของ Process ขนาดเล็กจะใช้เวลาเพียงเล็กน้อยก็ตาม

จากผลการทดลอง FCFS ของผม P1 ใช้ CPU เป็นเวลา 10 units
และเป็น Process แรกใน Queue ดังนั้น P1 จึงได้ทำงานตั้งแต่ Time 0
จนถึง Time 10 โดยที่ P2 และ P3 ยังไม่ได้ใช้ CPU

ผลคือ P2 ต้องรอ 10 units ก่อนเริ่มทำงาน และ P3 ต้องรอถึง
12 units ก่อนเริ่มทำงาน

จึงเห็นได้ชัดว่า P1 ซึ่งเป็นงานขนาดใหญ่ทำให้ Process ขนาดเล็ก
ที่ตามมาอย่าง P2 และ P3 ต้องรอนานขึ้น ซึ่งก็คือ Convoy Effect

ในทางกลับกัน เมื่อใช้ Round Robin ที่มี Time Quantum = 3
P1 จะไม่ได้ใช้ CPU ต่อเนื่องจนเสร็จ แต่จะใช้ได้ครั้งละไม่เกิน
3 units แล้วต้องให้ Process อื่นได้ใช้ CPU ต่อ ทำให้ P2 และ P3
สามารถเริ่มทำงานได้เร็วขึ้น

ผลที่ได้คือ Average Waiting Time ลดจาก 7.33 ใน FCFS
เหลือ 4.33 ใน Round Robin


2. Choosing the Time Quantum

Time Quantum คือจำนวนเวลาที่แต่ละ Process สามารถใช้ CPU
ได้ต่อหนึ่งรอบใน Round Robin

ถ้ากำหนด Time Quantum ใหญ่มาก เช่น Quantum = 100
และ Process ทุกตัวใช้ CPU น้อยกว่า 100 units Process แรกจะสามารถ
ทำงานจนเสร็จก่อนที่จะส่ง CPU ให้ Process ถัดไป

ในกรณีนี้ Round Robin จะเริ่มมีพฤติกรรมคล้ายกับ FCFS
เพราะแทบไม่มีการสลับ Process ระหว่างการทำงาน

แต่ถ้ากำหนด Time Quantum เล็กมาก เช่น Quantum = 0.0001
CPU จะต้องสลับจาก Process หนึ่งไปยังอีก Process หนึ่งบ่อยมาก

ทุกครั้งที่มีการสลับ Process ระบบต้องทำ Context Switching
ซึ่งมีค่าใช้จ่ายในการบันทึกสถานะของ Process เดิมและโหลดสถานะ
ของ Process ใหม่

ถ้าเกิด Context Switching บ่อยเกินไป CPU จะเสียเวลาไปกับ
การสลับ Process มากกว่าการประมวลผลงานจริง ทำให้ประสิทธิภาพ
ของระบบลดลง

ดังนั้น Time Quantum ไม่ควรใหญ่หรือเล็กเกินไป
ควรเลือกให้เหมาะสมเพื่อให้ระบบมีความยุติธรรมและไม่เสียเวลา
กับ Context Switching มากเกินไป
